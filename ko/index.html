FrameDoctor 사용자 가이드

씬에서 일어나는 일을 기록하고, 시간이 많이 드는 CPU 작업을 찾고, 직접 가한 변경이 도움이 되는지 확인하세요. Unreal Engine 프로젝트가 처음이어도 여기서 시작할 수 있습니다.

첫 기록 시작하기FrameDoctor 설치

  2. 근거 데이터 읽기
  3. 한 가지 변경
  4. 실행 결과 비교
  5. 결과 저장

프레임은 게임 화면 한 장입니다. 프레임 시간은 게임이 다음 프레임을 만드는 데 걸리는 시간입니다. 프레임 시간이 길면 화면이 멈추거나 끊기는 것처럼 느껴집니다. FrameDoctor는 시간 측정 이벤트가 담긴 트레이스 파일을 기록하고, 이 이벤트를 차트와 CPU 스코프 목록으로 보여 줍니다.

  • Capture: 실행 중인 씬을 기록합니다.
  • Findings: 프레임 시간을 읽고 개별 CPU 작업을 살펴봅니다.
  • Compare: 변경 전후에 보존해 둔 Development 빌드 두 개를 측정합니다.
  • Runs: 이전 기록을 다시 열고 근거 데이터를 내보냅니다.
  • Settings: 기록 프로필을 저장하고 임곗값을 선택합니다.
변경은 사용자가 직접 합니다. FrameDoctor는 조사와 측정을 돕습니다. 코드를 다시 쓰거나 게임을 자동으로 수정하지 않습니다. 분석은 로컬에서 실행됩니다.

가이드는 번역되어 있지만, 여기서 안내하는 플러그인 조작 항목은 영어 이름을 그대로 사용합니다. 언어 선택기는 이 가이드의 언어를 바꿉니다. 익숙하지 않은 Unreal 용어는 간단한 용어집에서 확인할 수 있습니다.

2

FrameDoctor 설치하고 열기

FrameDoctor는 Windows 64비트의 Unreal Engine 5.5, 5.6, 5.7, 5.8을 지원합니다. 사용하는 엔진 버전에 맞는 플러그인 패키지를 선택하세요.

Unreal을 처음 여는 경우

Epic Games Launcher → Unreal Engine → Library를 열고 설치된 엔진을 실행합니다. 기존 프로젝트를 열거나, Games → Blank → Blueprint를 선택하고 프로젝트 이름과 폴더를 입력한 뒤 Create를 클릭합니다. 프로젝트에는 게임이 저장되고, 레벨이라고도 부르는 맵에는 프로젝트 안의 씬 하나가 저장됩니다.

Fab에서 설치하기

  1. Unreal Editor를 닫습니다. 런처의 Fab Library에서 FrameDoctor를 찾아 Install to Engine을 클릭합니다.
  2. 프로젝트에 사용하는 엔진 버전을 선택하고 설치를 마칩니다.
  3. 프로젝트를 엽니다. Edit → Plugins에서 FrameDoctor를 검색하여 활성화하고, 다시 시작하라는 안내가 나오면 에디터를 재시작합니다.
  4. 에디터 기본 메뉴에서 Tools → FrameDoctor를 엽니다.

제공된 ZIP 설치하기

  1. 에디터를 닫고 플러그인의 압축을 풉니다.
  2. 압축을 푼 단일 FrameDoctor 폴더를 프로젝트의 Plugins 폴더에 넣습니다. Plugins가 없으면 만듭니다.

  4. 프로젝트를 열고 Edit → Plugins에서 플러그인을 활성화합니다. 다시 시작한 뒤 Tools → FrameDoctor를 엽니다.

Unreal에서 모듈을 컴파일하라고 하면 어떻게 하나요?

컴파일된 패키지에는 Binaries도 포함됩니다. 소스만 있는 패키지는 게임이 Blueprint를 사용하더라도 호환되는 C++ 컴파일러 도구 모음이 필요합니다. Visual Studio 2022에 Game development with C++와 엔진에서 요구하는 Windows SDK를 설치합니다. Blueprint 전용 프로젝트라면 Tools → New C++ Class에서 최소한의 클래스를 추가하여 C++ 프로젝트 타깃을 만듭니다. Unreal을 닫고 Visual Studio에서 프로젝트의 Development Editor / Win64 타깃을 빌드합니다. 그런 다음 프로젝트를 다시 엽니다. 컴파일이 실패하면 첫 번째 빌드 오류를 읽고 엔진과 패키지 버전이 맞는지 확인하세요.

3

첫 기록 만들기

씬 하나와 함께 제공되는 예제 시나리오로 시작하세요. 시나리오는 씬이 준비되고 측정을 시작할 수 있는 시점을 FrameDoctor에 알려 줍니다. 이 예제는 사용법을 배우고 씬을 조사하는 데 적합합니다.

  1. 맵을 열고 저장합니다. 조사할 씬을 연 뒤 File → Save All을 실행합니다.
  2. Play를 시작합니다. 에디터 도구 모음에서 삼각형 Play 버튼을 클릭합니다. 이를 Play In Editor, 줄여서 PIE라고 합니다. Shift + F1을 누르면 마우스가 해제되어 게임을 계속 실행하면서 에디터를 사용할 수 있습니다.
  3. Capture를 선택합니다. Tools → FrameDoctor → Capture를 엽니다. Use a packaged Development build는 선택하지 않은 상태로 둡니다. PIE는 이미 Play로 실행 중인 맵을 기록합니다. Map 필드에서 다른 맵을 선택해도 실행 중인 월드가 바뀌지는 않습니다.
  4. 예제를 선택합니다. Scenario에서 BP_ExploratoryScenario를 검색합니다. 에셋을 찾으려면 Content Browser를 열거나 Ctrl + Space로 Content Drawer를 열고, 해당 설정에서 Show Plugin Content를 켠 뒤 FrameDoctor Content → FrameDoctor → Examples를 살펴봅니다. 시나리오는 FrameDoctor에서 선택하며, 레벨로 끌어 놓지 않습니다.
  5. 기록합니다. 워밍업 10초와 측정 60초를 유지합니다. Preflight를 읽고 Capture running PIE를 클릭합니다. Play를 계속 실행하며 조사하려는 동작을 수행합니다. 워밍업은 측정 결과에서 제외됩니다.
  6. Findings를 읽습니다. 기록이 끝나면 Findings가 이미 선택되어 있지 않은 경우 엽니다. Capture quality and unavailable reasons를 읽고, CPU 스코프를 선택해 근거 데이터를 확인합니다.
첫 예제는 탐색용입니다. 이 예제의 설명은 재현 가능한 게임 조건을 확립하지 않습니다. 트레이스를 살펴볼 수는 있지만, A/B 효과를 확인하려면 조건을 제대로 기술한 시나리오와 Development 빌드 두 개를 사용하세요.

기록이 끝날 때까지 게임을 계속 실행하세요. Esc나 에디터의 Stop 버튼은 PIE를 종료하고 기록을 중단시킬 수 있습니다. FrameDoctor의 현재 작업을 취소하려면 FrameDoctor에서 Cancel을 사용하세요.

기록할 대상 선택하기

Capture에는 두 가지 대상이 있습니다. Use a packaged Development build가 선택되지 않으면 현재 PIE 월드를 기록합니다. 선택하면 FrameDoctor가 패키징된 게임을 별도로 실행합니다. 재현 가능한 변경 전후 측정에는 패키징된 게임을 사용하세요.

Capture 조작 항목
항목사용 방법
Baseline Development executableBrowse로 보존해 둔 빌드 A를 선택합니다. 이 경로는 Compare와 공유됩니다.
Map 및 Scenario시나리오 클래스를 선택합니다. Development에서는 쿠킹된 맵과 시나리오 클래스 경로를 지정합니다.
Warmup준비가 끝난 뒤 씬이 안정될 때까지 기다리는 시간입니다. 측정에서 제외됩니다.

일반 CPU 프로필은 cpu,frame,bookmark를 사용합니다. CPU 이벤트는 작업을 설명하고, frame 이벤트는 프레임 경계를 제공하며, bookmark는 측정 구간을 표시합니다. 외부 기록이 이미 실행 중이면 이를 끝내야 FrameDoctor가 자체 트레이스를 시작할 수 있습니다.

준비 완료, 워밍업, 측정 순서로 진행됩니다. Ready timeout과 Maximum trace size는 Settings에서 설정합니다. 취소되거나 중단된 기록은 상태와 함께 보관되지만, 완료된 비교 기준으로 사용할 수는 없습니다.

5

CPU 근거 데이터 읽기

기존 트레이스 열기

Import trace를 클릭하고 기록이 끝난 .utrace 파일을 선택한 뒤 Findings가 표시될 때까지 기다립니다. 가져오기 전에 기록을 중지하세요. 비교의 출처를 확인해야 한다면 트레이스 옆의 manifest.json과 원래 실행 기록의 파일들을 트레이스와 함께 보관합니다. Capture quality and unavailable reasons를 읽고 사용 가능한 CPU, 프레임, 측정 데이터를 확인하세요.

FrameDoctor의 측정 시작 및 측정 종료 북마크가 하나의 완전한 쌍으로 유일하게 확인되지 않으면 전체 트레이스를 탐색용 기록으로 분석합니다. 실행 매니페스트가 없거나 지원하지 않는 형식이면 기록의 완전성은 검증되지 않은 상태로 남습니다. 사용 가능한 이벤트를 살펴볼 수는 있지만, 검증되지 않은 데이터나 탐색용 데이터를 확인된 A/B 기준으로 사용할 수는 없습니다.

먼저 기록 상태와 품질을 확인하세요. 데이터가 불완전하거나 값이 Unavailable로 표시되면 Capture quality and unavailable reasons를 엽니다. 이는 값을 확정할 수 없었다는 뜻이며, 0이라는 뜻이 아닙니다.

  1. Game frame p95와 측정 시간을 읽습니다. 차트 곡선을 프레임 예산과 비교합니다.
  2. Search scopes…로 타이머 이름을 찾거나 All threads로 스레드를 선택합니다. 스레드는 CPU에서 실행되는 작업의 흐름입니다. GameThread는 보통 게임 로직을 실행합니다.
  3. 스코프 행을 클릭합니다. 패널에서 Measured(측정 내용), Interpretation(결과 해석), Next experiment(다음 실험), Behavior risk(동작에 미칠 위험) 설명을 확인합니다.
  4. Copy evidence로 선택한 타이머·스레드·구간을 식별하는 정보를 복사합니다. Open in Insights로 같은 트레이스를 Unreal Insights에서 열고 해당 구간으로 직접 이동합니다.

Exclusive / frame은 같은 스레드의 하위 스코프 시간을 뺀 스코프 시간을 유효한 프레임 전체에서 평균한 값입니다. Calls는 측정 구간 안에서 시작된 호출 수입니다. 스코프에는 대기 시간이 포함될 수 있습니다. 이름만으로 특정 에셋을 식별하거나 Blueprint 노드 하나의 비용을 입증할 수는 없습니다.

검색에는 표시 범위 제한이 있습니다. 표는 순위가 높은 첫 250개 행을 불러옵니다. 검색과 스레드 필터는 불러온 행에 적용됩니다. 나머지 스코프 집계는 전체 분석 JSON에 보관됩니다. 표를 원래대로 되돌리려면 Clear filters를 사용하세요.

프레임 비용을 추정하려고 중첩된 스코프의 포함 시간이나 병렬 스레드 시간을 더하지 마세요. 게임 프레임, 렌더 프레임, GPU 큐 문맥은 의미가 다릅니다. 신뢰할 수 있는 GPU 프레임 값이 없으면 해당 값은 계속 사용할 수 없는 상태로 남습니다.

6

프레임 시간 차트 살펴보기

가로축은 측정 중 흐른 시간이고, 세로축은 밀리초 단위의 프레임 시간입니다. 봉우리가 높을수록 느린 프레임입니다. 점선 예산선은 선택한 목표를 나타냅니다. 16.67 ms는 초당 약 60프레임에 해당합니다.

  • 확대·축소: 차트 위에서 마우스 휠을 사용하거나, 아래쪽의 작은 전체 보기에서 호박색 핸들을 끕니다.
  • 이동: 전체 보기에서 선택된 범위 안쪽을 끕니다. 차트에 키보드 초점이 있으면 왼쪽·오른쪽 화살표로 보이는 범위를 옮길 수 있습니다.
  • 값 확인: 차트 위로 포인터를 움직입니다. 시간 또는 집계 버킷, 샘플 수, 확인 가능한 최소·최대 시간이 표시됩니다.
  • 초기화: Reset view를 클릭합니다. Home 또는 Esc로도 초점이 있는 차트를 초기화할 수 있습니다.
확대·축소는 보이는 범위만 바꿉니다. 상단 p95 값, CPU 스코프 목록, 근거 데이터는 여전히 전체 측정을 사용합니다. 표시 범위를 좁혀도 그 구간에 맞춰 다시 계산하지 않습니다.

넓은 시간 범위를 표시하면 여러 프레임이 하나의 그리기 버킷에 묶일 수 있습니다. 이를 한 프레임으로 보지 말고 버킷의 샘플 수와 범위를 읽으세요. 프레임 데이터가 없는 구간은 빈 곳으로 남습니다.

7

Development 빌드 두 개 준비하기

Development 빌드는 개발 기능이 활성화된 상태로 에디터 밖에서 실행할 수 있는 패키징된 게임입니다. Baseline A는 원래 빌드이고, Candidate B는 의도한 변경 한 가지를 포함합니다. 각 빌드 전체를 별도 폴더에 보관하세요.

  1. 맵과 비교에 사용할 수 있는 시나리오를 저장합니다. 프로젝트에서 FrameDoctor를 활성화합니다.
  2. Edit → Project Settings → Packaging을 엽니다. List of maps to include in a packaged build에 맵을 포함합니다. 시나리오 Blueprint도 쿠킹되도록 합니다. 포함되는 콘텐츠에서 하드 참조를 유지하거나, 해당 폴더를 Additional Asset Directories to Cook에 추가합니다.
  3. 에디터의 Platforms → Windows 패키징 항목에서 빌드 구성으로 Development를 선택하고 프로젝트를 패키징합니다. 엔진 버전에 따라 메뉴가 다르게 묶여 있을 수 있습니다. 이 출력 전체를 빌드 A로 보관합니다.
  4. 시험할 변경 한 가지를 직접 적용합니다. 저장하고 다른 디렉터리에 빌드 B를 패키징합니다. 씬, 입력, 카메라, NPC, 기록 설정을 일관되게 유지합니다.
  5. Capture에서 Use a packaged Development build를 선택합니다. A의 실행 파일을 찾아 선택한 뒤 맵을 선택하고 시나리오의 생성 클래스 경로를 입력합니다.
Map: /Game/Maps/TestMap
Scenario: /Game/Scenarios/BP_TestScenario.BP_TestScenario_C
Executable: BuildA/Windows/YourProject/Binaries/Win64/YourProject.exe

에셋 이름은 자신의 프로젝트에 맞게 바꾸세요. /Game은 Unreal에서 보는 프로젝트의 Content 폴더이며, Windows 드라이브가 아닙니다. 생성된 Blueprint 클래스는 _C로 끝납니다. 콘텐츠를 포함해 패키징된 폴더 전체를 보관하세요. 실행 파일만 복사해서는 부족합니다.

Preflight는 요청한 설정을 검사합니다. 외부 빌드에 맵과 시나리오가 들어 있는지는 실제 로딩으로 확인됩니다. 기록은 개발용 구성을 위한 기능입니다. Shipping 및 Test 빌드는 FrameDoctor 기록을 할 수 없습니다.

변경이 도움이 되었는지 확인하기

  1. 앞의 설명대로 A와 B를 준비합니다. Compare에서 New Development comparison을 펼칩니다.
  2. Baseline Development executable과 Candidate Development executable을 선택합니다. Intended change에 무엇을 바꿨는지 정확히 적습니다.
  3. 실행 전에 Primary metric을 선택합니다. 느린 프레임에는 p95GameFrame, 평균 프레임 시간에는 meanGameFrame, 특히 느린 꼬리 구간에는 p99GameFrame을 사용합니다.
  4. 5쌍, 워밍업 10초, 측정 60초로 시작합니다. 의도한 빌드 변경에서 일반적으로 허용하는 차이는 gameBuildId만 남깁니다. 해상도, 그래픽 설정, VSync, 프레임 제한, 시나리오, 계측 설정을 일치시킵니다.
  5. Launch paired Development series를 클릭합니다. FrameDoctor는 보존한 빌드를 AB/BA 순서로 번갈아 실행합니다. 시리즈가 끝날 때까지 두 빌드 폴더를 변경하지 마세요.
  6. 판정과 그 이유, 쌍별 차이, 노이즈, 임곗값, 각 쌍의 원시 값을 읽습니다. 저장된 결과는 Open HTML report 또는 Open report folder로 엽니다.
비교 판정의 의미
판정다음 단계
Improved선택한 프레임 시간 지표가 확인 임곗값을 넘어 일관되게 감소했습니다. 게임플레이의 정확성은 별도로 확인하세요.
Regressed선택한 지표가 임곗값을 넘어 일관되게 증가했습니다. 변경을 조사하거나 되돌리세요.

InvalidComparison해당 실행 결과로는 유효한 비교를 할 수 없습니다. 불일치 또는 데이터 누락 이유를 읽고 먼저 바로잡으세요.

효과를 확인하려면 비교 가능한 조건과 함께 최소 5개의 완전한 쌍, 각 실행에서 측정 시간 30초와 완전하고 유효한 프레임 300개가 필요합니다. 더 짧은 기록은 탐색에 도움이 될 수 있습니다. 예제 탐색 시나리오로는 효과를 확인할 수 없습니다.

밀리초 값은 낮을수록 좋습니다. 쌍별 차이는 각 쌍의 B − A 차이의 중앙값입니다. 화면에 표시된 두 중앙값을 빼는 것과 다를 수 있습니다. 효과는 절대 임곗값, 상대 임곗값, 추정 노이즈 중 가장 큰 값을 넘어야 하며, 최소 80%의 쌍에서 방향이 같아야 합니다. 기본값은 0.5 ms와 5%입니다. 이 검사는 안정성을 판단하는 데 도움을 주지만, 그 자체로 원인을 확정하지는 않습니다.

완료된 시리즈를 다시 보려면 Import series and export report를 사용하고 해당 series.json을 선택합니다. 허용 차이를 지정해도 계측 설정이나 계산 방법의 불일치를 무시할 수는 없습니다.

9

근거 데이터를 다시 열고 공유하기

Runs를 열고 Refresh saved runs를 클릭합니다. 행을 선택하면 원본 세부 정보를 읽을 수 있습니다. 실행을 두 번 클릭하거나 Open selected evidence를 클릭하면 Findings가 다시 열립니다. 시리즈는 쌍별 비교 보고서가 열립니다.

기본 출력 위치는 <YourProject>/Saved/FrameDoctor이며, Settings에서 다른 출력 폴더를 선택할 수 있습니다. 단일 실행에는 원본 .utrace, 매니페스트, 분석이 보관됩니다. 시리즈에는 series.json, comparison.json, HTML 보고서, 원래 실행에 대한 참조가 보관됩니다.

  1. 공유할 시리즈를 불러옵니다.
  2. Include source traces in the export로 원본 트레이스를 포함할지 선택합니다. 상황에 맞게 Remove absolute paths and username from exported JSON을 켜 둡니다.
  3. Export paired series bundle을 클릭하고 내보낼 위치를 선택한 뒤 완료될 때까지 기다립니다.
  4. 내보낸 파일을 검토하고 결과를 검토할 사람에게 전체 번들을 보냅니다.
원시 트레이스는 원래 내용을 유지합니다. JSON의 정보 삭제 기능은 트레이스 안의 경로나 메시지를 제거하지 않습니다. 내보내기 체크박스 두 개는 기본적으로 모두 켜져 있습니다. 검토 패키지의 크기를 줄이려면 트레이스를 뺄 수 있지만, 옮긴 후 결과를 다시 확인하려면 받는 사람에게 원래의 유효한 실행 데이터와 원시 트레이스가 필요합니다.

Promote current run to baseline은 조건을 충족하는 완료된 비교 가능 실행을 <YourProject>/FrameDoctor/Baselines에 저장합니다. 짧은 기록이나 탐색용 기록은 해당하지 않습니다. 더 이상 조사하거나 재확인할 필요가 없을 때까지 원본 데이터를 보관하세요.

반복 가능한 시나리오 만들기

변경 전후의 효과를 확인할 준비가 되면 이 절차를 사용하세요. 시나리오는 실제 카메라, 입력, NPC, 난수 조건을 설정하고 설명해야 합니다. 훅은 Blueprint로 구현할 수 있습니다. 시나리오 작성에 C++는 필수가 아닙니다.

  1. Content Browser에서 Add → Blueprint Class → All Classes를 선택합니다. FrameDoctorScenario를 검색하고 프로젝트 콘텐츠에 BP_TestScenario를 만듭니다.
  2. 해당 Blueprint를 엽니다. Overrides 메뉴에서 아래 훅을 구현합니다. 이 객체는 기록 시 선택하며, 레벨에 배치하는 Actor가 아닙니다.
  3. Blueprint와 맵을 컴파일하고 저장합니다. FrameDoctor에서 클래스를 선택합니다. 패키징된 기록은 A와 B 준비의 설명대로 맵과 시나리오를 쿠킹에 포함합니다.
  4. 긴 비교를 시작하기 전에 짧은 탐색 기록을 한 번 실행하여 준비 완료 확인과 정리 작업을 점검합니다.

DescribeScenario에서 Make Frame Doctor Scenario Snapshot을 반환값에 연결합니다. 다음 필드에 실제 조건을 정확히 입력합니다.

  • ScenarioId / Revision: 비어 있지 않은 안정적인 식별자와 리비전입니다.
  • CameraRoute: 실제 고정 시점 또는 재현 가능한 경로입니다.
  • InputConditions: 사용하는 입력 또는 플레이어 입력을 배제하는 방법입니다.
  • NpcConditions: NPC 수와 행동입니다. NPC가 없는 경우도 명시합니다.
  • ParametersJson: 선택 항목인 유효한 JSON 객체입니다. 예를 들어 {"route":"fixed","npcCount":0}은 실제 씬을 설명할 때만 사용합니다.
  • SeedPolicy / RandomSeed: 그 시드로 게임의 난수를 실제 초기화했을 때만 Known, 난수를 사용하지 않을 때 NotUsed, 확인되지 않았을 때 Unknown으로 설정합니다.
  • DeclaredNondeterminism: 물리, 스트리밍, 운영체제 스케줄링처럼 남아 있는 변동 요인입니다.

시드 숫자를 적는 것만으로 게임이 초기화되지는 않습니다. 조건이 확인되지 않았다면 탐색용으로 남습니다. 포함된 BP_ExploratoryScenario는 의도적으로 빈 설명을 반환합니다.

Cleanup에서 다른 시스템의 액터나 기록을 제거하지 마세요. 성능을 변경한 뒤에는 게임플레이 동작을 별도로 확인하세요. 시간 측정 조건이 같다고 해서 새 로직이 올바르다는 뜻은 아닙니다.

12

제대로 동작하지 않을 때

Tools에 FrameDoctor가 없습니다

Edit → Plugins를 확인하고 FrameDoctor를 활성화한 뒤 다시 시작합니다. 패키지가 엔진과 맞는지, FrameDoctor.uplugin이 플러그인 폴더 바로 아래 있는지 확인합니다. 소스를 사용하는 경우 먼저 Development Editor 빌드를 마칩니다.

Capture running PIE를 사용할 수 없습니다

Play로 씬을 시작합니다. 패키징된 빌드 체크박스는 선택하지 않고, 구체적인 시나리오 클래스를 고른 뒤 다른 작업이 끝나기를 기다립니다. 탭을 사용하려면 Shift+F1으로 PIE 마우스를 해제합니다.

예제 시나리오가 보이지 않습니다

Content Browser 설정에서 Show Plugin Content를 켭니다. FrameDoctor의 Examples 폴더에서 BP_ExploratoryScenario를 검색한 뒤 Capture에서 해당 클래스를 선택합니다. 레벨에 배치하는 Actor가 아닙니다.

Ready timeout이 발생합니다

시나리오가 제한 시간 안에 준비되지 않았습니다. IsReady 오버라이드, 실제 액터·에셋, 맵, 쿠킹된 클래스 경로를 확인합니다. 기본 클래스는 false를 반환합니다. 실제 로딩에 시간이 필요하면 Ready timeout을 늘리되, 준비 상태 검사는 실질적인 조건을 확인하도록 유지합니다.

프레임 시간이나 배타 비용이 Unavailable입니다

프레임 시간에는 측정 구간 안의 frame 이벤트와 완전한 프레임이 필요합니다. 배타 CPU 비용에는 완전하고 일관된 스코프 계층도 필요합니다. cpu,frame,bookmark를 기록하고 실행을 유지하며 저장된 이유를 읽습니다. 사용할 수 없는 값을 0으로 취급하지 마세요.

비교가 Inconclusive 또는 InvalidComparison입니다

이유를 읽으세요. 모든 실행의 상태, 완전한 5쌍, 실행당 30초의 측정과 300개의 완전한 프레임, 충분히 설명된 시나리오, 안정적인 조건, 일치하는 계측 설정을 확인합니다. Inconclusive는 효과가 없다는 증거가 아닙니다. 차이를 해석하기 전에 유효성 문제를 바로잡으세요.

패키징된 빌드가 맵이나 시나리오를 찾지 못합니다

FrameDoctor를 활성화한 Development 빌드를 패키징합니다. 맵과 시나리오를 모두 쿠킹에 포함합니다. /Game/... 에셋 경로와 Blueprint 클래스 접미사 _C를 사용합니다. 보존한 전체 빌드 폴더에서 실행 파일을 선택합니다.

기록이 실패하거나 멈추거나 디스크 제한을 초과합니다

저장된 실행 상태와 이유를 읽습니다. 디스크 공간, 쓰기 권한, 트레이스 크기 제한, 다른 기록 도구가 실행 중인지 확인합니다. 새 기록에서는 이벤트 상세도나 시간을 줄입니다. Play를 계속 실행하고 측정 중에는 맵이나 그래픽 설정을 바꾸지 않습니다.

Open in Insights로 트레이스를 열 수 없습니다

엔진에 맞는 Unreal Insights 도구를 설치합니다. 원본 트레이스를 사용할 수 있도록 유지합니다. FrameDoctor는 같은 원본을 엽니다. 정확한 타이머·스레드·구간 이동은 수동입니다. 엔진이 비 ASCII 문자가 있는 경로를 열지 못하면 원본 기록을 보존하면서 간단한 ASCII 작업 경로를 사용합니다.

보고서는 열리지만 원본 트레이스가 없습니다

내보낸 보고서는 트레이스 없이 볼 수 있는 경우도 있지만, 재확인에는 원래의 유효한 원시 데이터가 필요합니다. 원본 트레이스를 포함한 새 번들을 내보내거나 원래 실행 폴더 전체를 복원합니다. JSON에서 정보를 삭제해도 누락된 트레이스가 생기지는 않습니다.
